前两节课，我们像指挥官一样让 LED 亮起来、闪起来。

但你们有没有发现一件事：它只是自己在那儿傻闪，不管我们在干嘛。

你冲它喊，它不理你；你挥手，它也不理你。它是个「瞎子」，也是个「聋子」。

为什么？因为到今天为止，信号一直是单向的——只有我们发给它，它没法感受我们。

今天我们要给 ESP32 装上「触觉」，让它能感受到我们的操作。

主角就是——按钮。

而且今天这节课会有一个特别有意思的意外：AI 写的代码，会让你按下去灯灭、松开反而亮。别急着说 AI 傻，那里面藏着一个硬件的小秘密。

键盘是哪种？鼠标呢？屏幕呢？待会儿课后任务就考这个。

第3课 本课难点 18–30 分

上拉陷阱：按下是 0，松开是 1

像一扇装了弹簧的门

松开按钮时（平时的样子）
弹簧把信号拉高
→
读到数字 1
松开 ＝ 1 —— 这是平时状态
按下按钮时
手指把信号按到地
→
读到数字 0
按下 ＝ 0 —— 反直觉，但硬件就是这样 → 判断要用 ==0
所以代码里要写 if btn.value() == 0: 才是「按下」

我打个比方，你们就懂了：想象一扇装了弹簧的门。

平时没人碰它，弹簧把门顶着，门是关着的——这就是「高」，读到数字 1。

现在你用手按下去，把门按到地上——这就是「低」，读到数字 0。

你一松手，弹簧又把它顶回去，又变回 1。

GPIO0 这个引脚就自带这么一根弹簧，它有个名字叫「上拉电阻」。

所以结论是反直觉的，但你必须记住：松开是 1，按下是 0。

我知道这很别扭。你按下去，感觉应该是「有了」，应该是 1 才对。但硬件不是这么设计的。

那代码要怎么改？原来写的是 == 1，现在要改成——== 0。

谁来说一遍：按下等于几？

今天三个新东西，一个一个读。

第一个，Pin.IN。IN 就是输入，外面的信号「进」到大脑里。上节课的 OUT 是往外发，方向正好相反。

第二个，if 和 else。if 就是「如果」，else 就是「否则」。

如果条件满足，就执行 if 后面缩进的代码；否则，就执行 else 后面缩进的代码。

我说一句可能有点大的话：机器的智商，就是从 if 开始的。在这之前我们写的程序只会照单执行；从今天起，它会自己做决定了。

第三个，也是最容易错的：判断相不相等，一定要用两个等号 ==！

一个等号 = 是「把值装进去」，两个等号 == 才是「问一问相不相等」。

写成一个等号会怎么样？直接报错。

还有两个小东西别忘：if 和 else 后面都有冒号，它们下面都要再缩进一格。

举手之前，先对着这三条自己查一遍。

第一条，缩进乱了。这是今天的头号错误。if 和 else 要左对齐——它们是一对，地位相同。它们下面的 led.value() 要再退一格。两层，数清楚。

第二条，忘了双等号。判断用 ==，两个。写成一个等号，PyCharm 直接报语法错。

怎么记？一个等号是「装进去」，两个等号是「问一问」。判断是在问，所以两个。

第三条，现象还是反的。那就是你的判断条件还是 ==1。改成 ==0。记住弹簧门：按下去贴地，是 0。

最后还有一种：按钮完全没反应。查两样——你按的是不是板子上那个 BOOT 按钮？还有，btn 定义的时候写的是不是 Pin.IN？写成 OUT 它就不听了。
