数字信号 vs 模拟信号

电灯开关 vs 调光旋钮

数字信号（之前学的）

只有两种：0 或 1

现象：开 / 关、亮 / 灭，非此即彼。
比喻：电灯开关——按下去就是开，弹起来就是关，没有中间。

VS
模拟信号（今天的新东西）

连续变化：0 ~ 4095

现象：渐亮渐暗、半明半暗，中间有无数个值。
比喻：调光旋钮——转到哪儿就是哪儿。

按钮、LED 都是数字的；光线、温度、声音这些真实世界的东西，大多是模拟的

这一页是今天的核心，慢慢讲。

左边，数字信号，我们前七节课玩的都是它。按钮：按下或松开。LED：亮或灭。只有两种状态，0 和 1。

比喻就是电灯开关——按下去是开，弹起来是关，中间没有第三种可能。

右边，模拟信号，今天的新东西。它的取值是连续的，从 0 一直到 4095，中间每一个数都可能出现。

比喻是调光旋钮——你转到哪儿就是哪儿，可以是一半亮、三分之一亮、百分之七十亮。

为什么是 4095 这个奇怪的数字？先不管，你只要知道：数字越大表示光越强，0 是最暗，4095 是最亮。

最后这条黑条很重要：按钮和 LED 是我们做出来的，所以是数字的；

而光线、温度、声音这些真实世界的东西，大多是模拟的——它们本来就是连续的。

所以从今天起，你们开始真正接触真实世界了。

数值一直是 0 或 4095？先查两样：AO 接的是不是 GPIO34、代码里有没有设量程

今天的新硬件是光敏模块。拿起来看，它上面有个小圆片，那就是感光的地方。

这块板子有个坑，我先说：它有两个输出脚。

一个叫 AO，A 是 Analog，模拟的意思。它输出 0 到 4095 的连续值——今天要接这个。

另一个叫 DO，D 是 Digital，数字的意思。它只输出 0 或 1，只能告诉你「黑还是不黑」。

别接 DO。接错了会怎么样？你的数字只会在 0 和 1 之间跳，看不到连续变化，然后你会以为模块坏了。

第三点：模拟值不是随便哪个脚都能读的。ESP32 只有部分引脚有这个本事，我们用 GPIO34。

接线看右边，四根线。老规矩：接线前先拔 USB。

最后那条提醒：如果你的数值一直是 0 或者一直是 4095，查两样——AO 是不是接在 GPIO34，还有代码里有没有那行设量程的。

第8课 参考代码 68–80 分

完整代码 · 自动小夜灯

完整可跑 · 读光 → 算亮度 → 调灯
from machine import Pin, ADC, PWM
import time

light = ADC(Pin(34))         # 光敏模块接 GPIO34
light.atten(ADC.ATTN_11DB)   # 量程设到 0~3.3V
led = PWM(Pin(2))            # LED 用「亮度百分比」控制
led.freq(1000)

while True:
    value = light.read()     # 读到 0~4095 的光线值
    print("light:", value)

    # 光线越暗(value越小)，灯越亮：反过来映射成亮度(0~1023)
    brightness = (4095 - value) // 4
    led.duty(brightness)     # 把亮度设为 brightness/1023 的百分比
    time.sleep(0.1)
看这一行：brightness = (4095 - value) // 4 —— 越暗越亮的秘密全在这里

这就是最终的自动小夜灯，完整能跑。

前面几行是准备：请工具、认元件。第 3 行请光敏模块，第 4 行设量程（这行不能少，少了数值会不对），第 5 行请 LED——注意这次用的是 PWM，因为要调亮度，不是开关。

下面 while 循环里是三件事，正好对应三步走：

第一件，value = light.read()，读光。读到 0 到 4095 的值。

第二件，也是今天最巧妙的一行——看黑条上那句：

brightness = (4095 - value) // 4

越暗越亮的秘密全在这里。 我拆开说。

光线读数 value：越暗，这个数越小。

那 4095 减去它呢？越暗，这个差越大。方向就反过来了。

再除以 4 是干什么？因为亮度档位的范围是 0 到 1023，而 4095 除以 4 正好约等于 1023。这是在换算单位。

第三件，把算出来的亮度交给灯。

最后停 0.1 秒，再来一轮。

你家的路灯、手机自动亮度、扫地机器人，背后都是这同一个闭环

停一下，我要你们看清楚今天真正做出来的是什么。

不是一盏灯。是一个会自己反应的系统。

它有三步。

第①步，输入。 光敏模块告诉板子：现在有多亮。这是机器的感觉。

第②步，处理。 那一行减法和除法，把「环境有多亮」换算成「灯应该多亮」。这是机器的思考。

第③步，输出。 把算出来的亮度交给灯。这是机器的动作。

感觉 → 思考 → 动作。这三步连起来，机器就能自己根据环境做反应，不用人管。

我告诉你们，这个闭环有多普遍：

你家小区的路灯，天黑自己亮——同一个闭环。

你的手机自动亮度，走到太阳底下屏幕变亮——同一个闭环。
