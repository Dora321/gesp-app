需求文档 ＝ 五要素

语言 · 硬件 · 接线 · 效果 · 约束——和提问五要素是同一套，写下来就是文档。

＋ 功能步骤清单

把效果拆成 ①②③④ 的小步，每一步都「问得到、做得到」。

文档即指挥：一份写清楚的需求文档，就是指挥 AI 的作战地图

什么叫需求文档？就是把「我到底想要什么」写清楚的说明书。

我打个比方。想象你要教一个完全不会泡茶的人泡茶。你不能只说「泡杯茶」——他站在那儿，一动不敢动，因为他不知道从哪下手。

你得说：先烧水、再放茶叶、把水倒进去、等三分钟。一步都不能少。

指挥 AI 也一样。你说得越清楚，它做得越对。

那需求文档里写什么？两部分。第一部分你们已经很熟了——五要素：语言、硬件、接线、效果、约束。以前是嘴上问，今天把它写下来，写下来就是文档。

第二部分是新的：功能步骤清单。把「效果」那一条拆成①②③④的小步。

这两样合起来，就是你指挥 AI 的作战地图。

第10课 对比 10–22 分

好需求 vs 坏需求

同一个抢答器，两种写法，AI 的反应天差地别

坏需求（太模糊）

「做个抢答器。」

AI 不知道：用什么硬件？接哪个脚？按下读到几？灯怎么亮？响多久？只能猜——猜错了怪谁？

VS
好需求（写清事实 ＋ 拆成步骤）

「按钮 GPIO14（PULL_UP，按下＝0）被按下时，点亮 GPIO2 的灯，蜂鸣器响 0.2 秒，松开复位。」

每个事实都有了，AI 不用猜。

「做个抢答器」五个字，AI 没法下手——模糊的需求，换来乱猜的代码

看左边这一句：「做个抢答器。」

五个字，你觉得说清楚了吗？我们站在 AI 的角度想一想，它会有多少个问题：用什么硬件？按钮接哪个脚？按下读到的是 0 还是 1？灯接哪儿？怎么算「亮」？响多久算一声？松开之后呢？

七八个问题，它一个都不知道。它只能猜。猜错了，代码就是错的——这能怪 AI 吗？

再看右边。同一个抢答器，换一种写法：按钮 GPIO14，上拉，按下等于 0；按下时点亮 GPIO2 的灯；蜂鸣器响 0.2 秒；松开复位。

每一个事实都写清楚了，AI 一个都不用猜。

所以今天这节课最重要的一句话，我先说一遍，待会儿还要再说一遍：AI 猜错，多半是我们没说清。

需求文档范例：一键抢答器

五要素

语言MicroPython

左边五要素。前三条很快能填完。我重点讲两条。

什么时候、发生什么、持续多久——这三样都得有，缺一样 AI 就得猜。

下半场第一件事：拆步骤。这是今天最难的一关，我们一起拆。

「做个抢答器」这五个字，AI 不知道从哪下手。我们把它拆开——我问，你们答。

第一步，要让程序知道什么？对，怎么知道按钮被按了。

第二步，知道被按了以后呢？点亮 GPIO2 的灯。

第三步，光亮灯够吗？还要响——蜂鸣器响 0.2 秒。

第四步，一直亮着行不行？不行，松手要复位：灭灯、停响，回到等待。

第五步，做完一次就结束了吗？不行，要用 while 循环一直重复。

把一件大事，拆成五件小事。每件事都短得能一句话说清。

检验标准记住三个词：问得到、做得到、验得了。做不到这三点，说明还得再拆细。

现在把你们的清单补进文档。

第10课 第②③步 60–74 分

按下亮灯 ＋ 响一声

接着上一步问：「现在 LED 接 GPIO2、蜂鸣器接 GPIO13（有源）。请改成：按下按钮时点亮 LED，并让蜂鸣器响约 0.2 秒。」
第②③步 · 起步全码（完整可跑）
from machine import Pin
import time

button = Pin(14, Pin.IN, Pin.PULL_UP)  # 和第①步一样
led = Pin(2, Pin.OUT)                  # LED
buzzer = Pin(13, Pin.OUT)              # 蜂鸣器

while True:
    if button.value() == 0:            # 0 = 按下
        led.value(1)                   # 灯亮
        buzzer.value(1)                # 开始响
        time.sleep(0.2)                # 响 0.2 秒
        buzzer.value(0)                # 停响
if button.value() == 0: 这个 0 就是文档里那句「按下＝0」——写对了，AI 才不会猜反

第②③步一起做，因为它们都发生在「按下的那一瞬间」。

提问还是那个套路：在刚才的基础上加新硬件、加新效果，约束不变。注意我把「有源」两个字写进去了——蜂鸣器分有源和无源，有源的用 value(1) 就响，无源的得用 PWM。型号不说清，AI 又得猜。

看代码里这一行：if button.value() == 0。这个 0 从哪来的？从你们文档的接线栏来的，就是那句「按下＝0」。

写对了，灯就按下亮；写成 1，一会儿你们就会看到什么叫「全反了」。

还有一点：if 下面那几行往里缩进四个空格，表示「按下的时候才做这些事」。缩进错了，程序就乱了。

动手，跑通的组举手。

第10课 第④⑤步 60–74 分

松开复位 ＋ 一直循环

接着上一步问：「请加上：松开按钮后熄灭 LED、停止蜂鸣，并用 while 循环让它一直工作。」
第④⑤步 · 完整可运行参考代码（抢答器）
from machine import Pin                # 引脚工具
import time                            # 时间工具

button = Pin(14, Pin.IN, Pin.PULL_UP)  # 按钮：上拉，按下=0
led = Pin(2, Pin.OUT)                  # LED
buzzer = Pin(13, Pin.OUT)              # 蜂鸣器

while True:                            # 一直守着
    if button.value() == 0:            # 读到 0 = 有人按下
        led.value(1)                   # 灯亮——抢到了
        buzzer.value(1)                # 响
        time.sleep(0.2)                # 响 0.2 秒
        buzzer.value(0)                # 停响
    else:
        led.value(0)                   # 松开就灭灯，回到等待

最后两步，一句话就问完了：松开后熄灭、停响，并且用 while 循环一直工作。

看代码，新东西只有两行：else，还有它下面的 led.value(0)。

else 是什么意思？「否则」——如果按钮没有被按下，就把灯灭掉。

有同学会问：那前面不是已经有 while True 了吗？对，while True 是「一直守着」，但守着的时候要分两种情况：按下了怎么办，没按下怎么办。if 管第一种，else 管第二种。

注意 else 要和 if 对齐，它下面那行再往里缩进四格。缩进错了，灯就不灭。

这就是完整的抢答器了。跑起来试试——按住，灯亮、响一声；松开，灯灭。

第10课 AI 出错时刻 74–82 分

灯怎么反着亮？

一上电常亮，一按反而灭——效果全反了

AI 给的代码
while True:
    if button.value() == 1:
        led.value(1)

# 一上电灯就常亮
# 一按按钮反而灭——全反了！

病因

文档接线栏只写了「按钮接 GPIO14」，没写「按下读到的是 0」——AI 不知道这个事实，只能猜，猜成了 ==1

补一句约束再问

「按钮用 PULL_UP，按下＝0。请按这个事实检查并改正判断条件。」

验收三查：① 能跑吗　② 效果对吗　③ 有没有看不懂的魔法

我看到好几组举手说「老师，灯反了」——一上电灯就常亮，一按按钮反而灭。

停一下，全班看屏幕。先别骂 AI。

验收三查：能跑吗？能跑，不报错。效果对吗？不对，全反了。有没有看不懂的魔法？没有。

问题出在第二条。那我们回头看——看哪儿？不是看代码，是看我们自己的文档。

接线栏里，你写了「按钮接 GPIO14」，对不对？那你写没写「按下读到的是 0」？

（停一下，让他们翻文档）

没写。所以 AI 不知道这个事实，它只能猜。它猜按下是 1——在别的板子上这么猜也不算错，但在我们这块上是反的。

怎么办？不用重开一轮，在文档里补一句约束，再问一次：「按钮用 PULL_UP，按下＝0，请按这个事实检查并改正。」
