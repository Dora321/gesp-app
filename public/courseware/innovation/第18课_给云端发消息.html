上云要报三样东西。还是用快递柜打比方。

第一样：服务器。 去哪家快递柜？

我们用的是巴法云，地址是 mqtt.bemfa.com，端口 9501。

这里有个坑，我用红笔圈出来：不是 bemfa.com，是 mqtt.bemfa.com。差三个字母，连不上。

第二样：私钥。 你是谁？

巴法云会给你一串字符，那就是你的身份证。代码里它当 client_id 用。

我强调一句：这是你家钥匙，谁也不给。 泄露了，别人就能往你的柜子里塞东西、拿东西。真泄露了怎么办？去后台重新生成一个。

第三样：主题名。 放哪个柜子？

按学号编号，比如第 3 组的温度就是 g3temp01。

而且结尾一定要加 /up。

/up 是什么意思？——「只存柜、别敲门」。

不加会怎么样？每传一次数据，平台就往手机推一条消息。全班二十组、每 30 秒一次……

全班的手机会被敲爆。

这是全班的主题命名规范，贴墙上。

规则很简单：第 N 组 → gN ＋ 用途 ＋ 序号 ＋ /up。

第 3 组的温度就是 g3temp01/up。湿度是 g3hum01/up，光照是 g3light01/up。

为什么要定这个规范？

因为巴法云上，所有人的柜子在一起。你随便起个名字叫 temp，可能全国有一百个人也叫 temp——那你们的数据就混在一起了。

加上组号前缀，就是「这是第 3 组的柜子」，谁也不占谁的。

最后黑条上那句，是今天最常见的故障：

主题名差一个字母，就是别人家柜子。

控制台看不到自己的数据？先查主题名，一个字母一个字母对。

还有一个常见的：结尾漏了 /up。数据是进去了，但是进错柜子，还把全班的手机敲了。

第18课 第①步 22–40 分

先连上云，再谈上传

五要素 · 只要连云这一块：「请写代码：连上 WiFi，再用 umqtt 连接巴法云（服务器 mqtt.bemfa.com，端口 9501，私钥当 client_id），连上后打印『已连上云』。约束：只要连接这一块，带中文注释。」
起步全码 · 第①步：连 WiFi ＋ 连云
import network, time                 # 联网、计时工具
from umqtt.simple import MQTTClient  # MQTT 上云工具

WIFI_SSID = "你的WiFi名"
WIFI_PASS = "你的WiFi密码"
BEMFA_KEY = "你的巴法云私钥"        # 私钥当 client_id

wlan = network.WLAN(network.STA_IF); wlan.active(True)
wlan.connect(WIFI_SSID, WIFI_PASS)
while not wlan.isconnected():        # 等连上
    time.sleep(0.5)
print("已联网", wlan.ifconfig()[0])
# 服务器是 mqtt.bemfa.com，端口 9501（不是 bemfa.com！）
client = MQTTClient(BEMFA_KEY, "mqtt.bemfa.com", 9501)
client.connect()
print("已连上云")

还是老规矩：一次只搭一块。这一步先不接传感器，只做一件事——连上云。

为什么要分开？因为如果一次全写，出了问题你不知道是网的问题、云的问题、还是传感器的问题。

先把云连上，打印出「已连上云」这五个字，这一步就过了。

看代码。前半段是上节课的老朋友：连 WiFi、等连上、打印 IP。一模一样，你们已经会了。

新的只有最后三行：

client = MQTTClient(BEMFA_KEY, "mqtt.bemfa.com", 9501) —— 三件套齐了：私钥当 client_id，服务器地址，端口。

client.connect() —— 连上去。

print("已连上云") —— 成功的标志。

最容易出的错，我提前说：连接被拒，报 MQTTException: 5。

99% 是私钥抄错。逐字核对，别把主题名误填成私钥了——这两个都是一串字符，很容易搞混。

第18课 第②步 22–40 分

每 30 秒，上传一次温度

完整可运行参考代码 · 数据上云
import network, time, dht            # 多请一位帮手：dht
from machine import Pin
from umqtt.simple import MQTTClient

WIFI_SSID = "你的WiFi名"
WIFI_PASS = "你的WiFi密码"
BEMFA_KEY = "你的巴法云私钥"        # 私钥当 client_id
TOPIC = "g1temp01/up"              # 学号前缀 g1 换成你的；/up = 只存云不推送

wlan = network.WLAN(network.STA_IF); wlan.active(True)
wlan.connect(WIFI_SSID, WIFI_PASS)
while not wlan.isconnected():
    time.sleep(0.5)
print("已联网", wlan.ifconfig()[0])
client = MQTTClient(BEMFA_KEY, "mqtt.bemfa.com", 9501)
client.connect()
print("已连上云")

sensor = dht.DHT11(Pin(14))          # DHT11 接 GPIO14
while True:
    sensor.measure()                 # 先测一次（忘了会报错）
    t = sensor.temperature()
    client.publish(TOPIC, str(t))    # 传字符串即可
    print("已上传", t, "℃")
    time.sleep(30)                   # 每 30 秒传一次，别刷屏

这是完整版。在第①步的基础上，加了传感器和上传。

新增的部分只有最后几行，我们看循环里面：

sensor.measure() —— 先测一次。第 7 课和 L13 都强调过：忘了它，一运行就报错。

t = sensor.temperature() —— 取出温度。

client.publish(TOPIC, str(t)) —— 这就是「放进柜子」。

注意 str(t)：传字符串即可。温度是个数字，要先转成文字再传。

time.sleep(30) —— 每 30 秒传一次。

为什么是 30 秒不是 1 秒？两个原因：一是没必要，温度一秒变不了多少；二是别刷屏，平台也有额度。

还有最上面那行 TOPIC = "g1temp01/up"——把 g1 换成你自己的组号。

这是今天唯一一个每组都不一样的地方，改错了数据就进了别人柜子。

现在动手。跑起来之后，串口应该每 30 秒打印一次「已上传 XX ℃」。

第18课 AI 出错时刻 65–80 分

联网代码越长，越要一行行验收

AI 给的上传代码，最常见两个坑

AI 给的代码（两处坑）
TOPIC = "g1temp01"        # 漏了 /up ！

while True:
    t = sensor.temperature()   # 漏了 measure() ！
    client.publish(TOPIC, str(t))
    time.sleep(30)

# 结果一：一运行就报错（没 measure）
# 结果二：全班手机被推送刷屏（没 /up）

坑一：忘了 measure() / 坑二：漏了 /up

忘 measure → 一运行就报错（好发现）。
漏 /up → 数据进了别人柜子，还触发推送，全班手机刷屏（不报错，最阴）。

别急着重问，用追问让它自己补

「上传后控制台没更新，是不是读传感器前少了 measure()？主题名末尾是不是漏了 /up？请检查并改好。」

验收三查：① 能跑吗　② 数据在控制台更新了吗　③ 有没有看不懂的魔法

AI 给的上传代码，最常见两个坑，我都放在这一页了。

坑一：忘了 sensor.measure()。

后果是一运行就报错。这个反而好——红字会告诉你。

坑二：主题名末尾漏了 /up。

后果是什么？数据进了别人柜子，而且触发推送——全班手机开始刷屏。

而且这个坑不报错。程序跑得好好的，串口也打印「已上传」，就是全班在骂你。

（学生会笑）

这又是我们说过好多次的那类错：不报错的错，最阴。

怎么办？别急着重开一轮问，用追问：

「上传后控制台没更新，是不是读传感器前少了 measure()？主题名末尾是不是漏了 /up？请检查并改好。」

这就是第 6 课学的追问话术①和③的组合用法。

最后我要说今天这一阶段的核心心法：

联网代码越长，越要一行行验收。

AI 是协作伙伴——但把关永远是我们的活儿。
