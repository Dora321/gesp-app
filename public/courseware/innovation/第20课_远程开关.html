这一页是今天的核心，我要讲慢一点。

联网只有两个方向，对应两个词。

左边是上传，L18 学过的。设备往云里 publish——「放包裹」。主题带 /up。

右边是控制，今天学的。设备 subscribe 一个主题，然后守着——「取留言」。主题不带 /up。

为什么控制主题不带 /up？

还记得 /up 是什么意思吗？——「只存柜、别敲门」。

可控制就是要敲门啊！你点了 on，云必须主动推给设备，它才知道要亮灯。

所以控制主题绝对不能带 /up。这是今天第一个坑。

中间还是那个快递柜。注意这句话：设备和人从不直接见面，两边都只跟柜子打交道。

最后黑条上那句，我要你们背下来：

写联网代码前先问：这段是放包裹，还是取留言？

方向搞反，代码全对也不动。 一个红字都不报，就是不动。

第20课 第①步 22–40 分

写好「收到就干活」的回调

五要素 · 只要回调这一块：「请写代码：订阅巴法云主题 g1led01，收到字符串 on 就点亮 GPIO2 的 LED，收到 off 就熄灭。约束：回调函数带 topic 和 msg 两个参数，msg 先 decode() 成字符串再比较，只用学过的写法。」
起步全码 · 第①步：收到就干活
import network, time
from machine import Pin
from umqtt.simple import MQTTClient

WIFI_SSID = "你的WiFi名"
WIFI_PASS = "你的WiFi密码"
BEMFA_KEY = "你的巴法云私钥"
TOPIC = "g1led01"          # 控制主题：不带 /up
led = Pin(2, Pin.OUT)

def message_callback(topic, msg):   # topic 参数必须留
    msg = msg.decode()              # 字节→字符串
    if msg == "on":  led.value(1)
    elif msg == "off": led.value(0)

今天的新东西叫「回调」。名字有点吓人，其实很简单。

回调 ＝ 「收到留言之后，该干什么」。

你先把这件事写好放在那儿，等云真的送留言来了，它自动被叫起来执行。

看代码最后那个 def message_callback(topic, msg)。

这里有两个坑，都在这一行和下一行，我一个一个说。

坑一：topic 参数必须留着。

就算你用不上它，也不能删。因为库固定传两个东西过来：主题和消息。你只写一个参数，一调用就报错。

坑二：msg = msg.decode()。

云送过来的 msg 是字节，不是字符串。你直接拿它跟 "on" 比，永远不相等——不报错，就是不动。

decode() 的意思就是「把字节翻译成字符串」。

这两个坑，AI 很容易写漏。所以我把它们写进了约束里。

剩下的 if/elif 你们早就会了：收到 on 就 value(1)，收到 off 就 value(0)。

第20课 第②步 22–40 分

连云 ＋ 订阅 ＋ 等指令

接在第①步后面，合起来就是完整程序

起步全码 · 第②步：守着柜子等留言
wlan = network.WLAN(network.STA_IF); wlan.active(True)
wlan.connect(WIFI_SSID, WIFI_PASS)
while not wlan.isconnected(): time.sleep(0.5)
client = MQTTClient(BEMFA_KEY, "mqtt.bemfa.com", 9501)
client.set_callback(message_callback)
client.connect(); client.subscribe(TOPIC)   # 订阅
while True:
    client.check_msg()      # 有没有新指令？
    time.sleep(0.1)
check_msg() 必须在循环里——它是「去柜子看一眼有没有新留言」，只看一次就不看了，等于没订阅

第②步。前四行是老朋友：连 WiFi、连云。你们已经写过两遍了。

新的是这三行：

client.set_callback(message_callback) —— 告诉云：留言来了，叫这个函数。

把第①步写好的回调挂上去。

client.subscribe(TOPIC) —— 订阅。就是跟云说：「这个柜子有留言，记得通知我。」

然后是循环里那一行，今天最容易漏的一行：

client.check_msg() —— 「去柜子看一眼，有没有新留言？」

黑条上写了：它必须在循环里。

为什么？因为 check_msg 只是看一眼。看完这一眼，它就回来了。

你要是把它写在循环外面，就等于只看了一次——之后再有留言，它也不知道。

只看一次就不看了，等于没订阅。

最后 time.sleep(0.1) —— 每 0.1 秒看一眼。够快了，你按下按钮到灯亮，人感觉是瞬间的。

点了没反应？三处逐一查

三个最容易错的地方

点了没反应，是今天最常见的状况。而且——它不报红字。

我把四个坑都列在这一页了。

错 1：控制主题带了 /up。 云只存不推，设备永远收不到。

① 主题名对吗（不带 /up）② check_msg 在循环里吗 ③ 指令是 on/off 还是别的词

今天三个发现。

第一个，两个方向、两个词。放包裹是 publish，主题带 /up；取留言是 subscribe，主题不带 /up。

这两个词你们记牢，后面所有联网的东西都逃不出它们。

第二个，回调就是「收到留言之后该干什么」。先写好放在那儿，等云来叫它。

这个想法其实很像现实生活：你在快递柜登记了手机号，不是你一直守着，是有包裹了它通知你。

第三个，check_msg() 必须在循环里。
