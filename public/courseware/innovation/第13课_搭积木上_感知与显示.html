现在接线。注意——照着你自己画的设计图接，不是照我的。

每组的项目不一样，接的东西也不一样。你图上写的是光敏，就接光敏；写的是 DHT11，就接 DHT11。

第一条，老规矩：先拔 USB 再接线。三不碰。

第二条，接感知元件。光敏接 GPIO34，DHT11 接 GPIO14。

第三条，顺手把 LED 接到 GPIO2。为什么今天就接 LED？它是执行段的东西啊。

起步全码 · 主线：智能小夜灯（感知＋显示）
from machine import Pin, ADC       # 引脚与模拟读取工具
import time                        # 时间工具

light = ADC(Pin(34))               # 光敏模块接 GPIO34
light.atten(ADC.ATTN_11DB)         # 量程调到 0~3.3V（别忘！）
led = Pin(2, Pin.OUT)              # LED 接 GPIO2

while True:
    value = light.read()           # 感知：读亮度（0~4095）
    print("亮度：", value)         # 显示：打印到串口
    led.value(1)                   # 点亮 LED 确认接线
    time.sleep(1)                  # 每秒读一次

现在向 AI 要代码。看第⑤条约束，今天这条最关键：

「只要这一个模块的代码」。

这七个字是今天的护身符。不写它，AI 很容易热心过头，把整个小夜灯都给你写了。

下面是你们应该拿到的代码，大概长这样。我带你们读一遍——要到的代码，先自己读一遍，每行干嘛的能说清楚，再上板跑。

第 1、2 行请工具。

第 4 行请光敏管家，站在 34 号脚。

第 5 行——设量程。后面括号里我写了「别忘！」。为什么要提醒？待会儿的 AI 出错时刻就是它。

第 6 行请 LED。

下面循环里三件事：读、打印、点亮 LED，然后停 1 秒。

这就是「感知 ＋ 显示」：读是感知，打印是显示，LED 是确认接线。

第13课 附录范例 22–40 分

温度组：感知 ＋ 显示

做温度警报器的组看这一页——提问把第一句换成「DHT11 接 GPIO14，OLED 接 SCL=22/SDA=21」

起步全码 · 桌面温度警报器（感知＋显示）
from machine import Pin, SoftI2C   # 引脚与 I2C 工具
import dht, time                   # DHT11 与时间工具
from ssd1306 import SSD1306_I2C    # OLED 驱动（板上要先传 ssd1306.py）

sensor = dht.DHT11(Pin(14))        # DHT11 接 GPIO14
i2c = SoftI2C(scl=Pin(22), sda=Pin(21))
oled = SSD1306_I2C(128, 64, i2c)   # OLED 屏

while True:
    sensor.measure()               # 先测一次（别忘！）
    t = sensor.temperature()       # 取出温度
    oled.fill(0)                   # 清屏
    oled.text("Temp: " + str(t) + "C", 0, 0)
    oled.show()                    # 显示到屏上
    time.sleep(2)                  # DHT11 至少隔 1~2 秒再读
DHT11 读之前必须先 measure()，而且两次读取至少隔 1~2 秒——少一样就报错

做温度警报器的组看这一页。结构和主线完全一样，只是元件换了。

提问的时候，把第一句换成：「DHT11 接在 GPIO14，OLED 接 SCL=22、SDA=21」，效果换成「读出温度并显示到 OLED」。

代码里有两个坑，我都用括号标出来了。

第一个，第 3 行 from ssd1306 import SSD1306_I2C——板上要先传 ssd1306.py。第 4 课踩过，今天别再踩。

第二个，循环里第一行 sensor.measure()，「先测一次」。

DHT11 有个脾气：你不能直接问它「现在几度」，得先让它去测，再取结果。少了 measure() 这一行，直接报错。

还有黑条上那句：两次读取至少隔 1~2 秒。所以最后 sleep 写的是 2 不是 1。

这两个坑，一个报错、一个不报错——不报错的那个更可怕，下一页就讲。

屏幕上跳出数字了，是不是就成功了？

没有。

我给你们讲一个真事：每年都有组，串口里数字刷得飞快，一看 4095、4095、4095……他们很开心，说读到了。

我走过去，用手把光敏捂住——还是 4095。

那它读的是什么？不是光。

所以今天最重要的一句话是：先看到，再相信。

「看到」是第一步：把数据显示出来。串口打印，或者 OLED 显示。

顺便看一眼 LED 亮没亮。亮了说明板子活着、代码传上去了——这是最便宜的排错手段，两秒钟排除一半问题。

「相信」要靠验证：

光敏组，用手遮住它——数值应该变小。

温度组，对着传感器哈口气——温度应该往上动。

数值会跟着环境变，才说明它真的在感知。
