AI 为什么胡说八道

屏幕有很多种：有大有小、有彩色有黑白、有 I2C 有 SPI。你不告诉它型号，它只能随便猜一个——结果鸡同鸭讲。

编程里管这个翻译软件叫「库（Library）」。没装对库，板子根本听不懂这块屏幕的话。

我们先读一读这个红字：ImportError: no module named ... 翻译过来就是——「我找不到这个东西」。

为什么找不到？两个原因。

第一，屏幕有很多种。有大有小，有彩色的有黑白的，接口也不一样。你不告诉 AI 具体的型号，它就随便猜了一个，结果鸡同鸭讲，根本对不上。

第二，它还需要一个「翻译软件」。

什么意思？板子的大脑本来不认识这块屏幕，它们语言不通。得装一个专门的翻译软件，板子才能跟屏幕对话。

这个翻译软件，我们编程里管它叫「库」，英文 Library。

所以红字里的 ImportError，说白了就是：我找不到这个翻译软件。

第4课 参考代码 18–30 分

from machine import Pin, SoftI2C
import ssd1306

i2c = SoftI2C(scl=Pin(22), sda=Pin(21))
oled = ssd1306.SSD1306_I2C(128, 64, i2c)

oled.fill(0)               # 清空屏幕
oled.text('Hello', 0, 0)   # 准备文字和坐标
oled.show()                # 显示出来
这段是顺序执行的，没有循环也没有判断——所以不需要缩进

这就是正确的完整代码，九行，能直接跑。

六行，一行一行读。

第一行，import ssd1306。这句话就是对大脑说：快把针对这块屏幕的翻译软件拿出来。这个翻译软件，就叫库。

第二行，SoftI2C，两根特别聪明的通信线：SCL 管节奏，SDA 传数据。就像两个人抬东西，一个喊号子，一个真扛。

第三行，告诉它屏幕多大：128 宽、64 高。单位是什么？是小格子，一个格子就是一个点。

第四行，fill(0)，先把屏幕擦干净。0 就是全黑。为什么要擦？因为上一次显示的东西可能还留在上面。

第五行，text('Hello', 0, 0)——在坐标 (0,0) 的位置写 Hello。(0,0) 是哪儿？左上角。

最后一行最重要：oled.show()。

我打个比方：前面那行 text 只是起草，就像你在纸上画好了画；show() 才是举起来给大家看。

不写这句会怎么样？程序不报错，但屏幕一片黑。这是今天最阴险的一个坑。

屏幕上写字，其实就像在一张网格纸上找位置。

记住三条。

第一，原点在左上角，坐标 (0, 0)。注意——不是左下角，跟你们数学课上画的坐标系不一样。

第二，X 越大越靠右，屏幕一共 128 格宽。

第三，Y 越大越靠下，屏幕一共 64 格高。注意 Y 是越大越往下，这个也和数学课相反。

那如果我想把字放在正中间，X 和 Y 大概填多少？

（等他们算）

128 的一半是 64，64 的一半是 32。但字本身有宽度，所以往左上挪一点，大概填 (40, 28) 就差不多在中间了。

还有一条提醒：如果你填的数字太大，超出屏幕了，程序不会报错，但字会被切掉一半，或者干脆看不见。别以为是代码坏了。

三个高频错，自己先查

今天的报错有点多，别慌——每个红字都在告诉你哪儿错了

ImportError

板子里没有库文件。把 ssd1306.py 上传到 ESP32 就好。

OSError: ENODEV

线接反了或接触不良——多半是 SCL 和 SDA 弄反了，或者线没插紧。

不报错但屏幕全黑

忘了 oled.show()——文字只是起草了，没「举起来」。

今天的报错比前几课多，这很正常——因为我们第一次接外部元件了。

三个高频错，举手之前自己先查。

第一，ImportError。老朋友了，意思是找不到库。板子里没有那个文件。去 MicroPython Tools 面板把 ssd1306.py 上传到板子。

第二，OSError，后面跟着 ENODEV。这个词的意思是「找不到设备」——线的问题。多半是 SCL 和 SDA 接反了，也可能是线没插紧。拔了 USB，重新接一遍。

第三个最阴，不报错，但屏幕全黑。

这种最容易让人怀疑人生，因为电脑告诉你「一切正常」。查什么？查最后一行——oled.show() 写了没有。

还有一种是屏幕上显示乱码，花花绿绿一片。那是库和屏幕型号对不上——比如你手里是 SH1106 的屏，用了 SSD1306 的库。找我换一块。
