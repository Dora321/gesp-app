认识今天的新硬件，WS2812 灯带。它和我们之前用的 LED 有什么不一样？

第一，它是一串的，这条上面有十颗，每一颗都有自己的编号，从 0 到 9。第二，每一颗都能单独变色，靠三个数字：红、绿、蓝，各从 0 到 255。我们课堂上有个约束，亮度不要超过 80，太亮刺眼睛。

第三点最重要，也是最容易出事的：灯带有方向。你看这一端标着 DIN，或者有个箭头，数据只能从这一头流进去。接反了，一颗都不亮，代码写得再对也没用。

接线之前，先做什么？先拔 USB。实验室三不碰：不湿手碰、不短接、不带电插拔。

十颗灯接 3.3V 一般够用；万一发暗，再改接 5V——记住，改线之前还是要先拔 USB。

有同学已经在想彩虹了，先停一下。今天我们练的是一个方法，比彩虹更值钱：把大任务拆成小步。

为什么要拆？因为一次问一大堆，AI 给你一坨代码，错了你都不知道错在哪一步。拆开问，每一步都能当场验收，错了立刻就知道是哪一段。

每一步提问都要带五要素：语言、硬件、接线、效果，还有第五个——约束。约束是这一阶段新加的，也是最容易忘的。

比如这样写：「只用 neopixel 和 time 这两个工具，亮度不要超过 80，代码带中文注释。」

你不写约束，AI 就可能给你一个从没见过的库，那就是超纲魔法，我们不要。

from machine import Pin              # 引脚工具
import neopixel                      # 灯带工具箱

np = neopixel.NeoPixel(Pin(5), 10)   # 数据脚 GPIO5，管 10 颗灯
np[0] = (80, 0, 0)                   # 第 1 颗灯的编号是 0，填上红色
np.write()                           # 把颜色送给灯带
看清楚：第 1 颗灯的编号是 0，不是 1；最后那行 np.write() 少了就一片漆黑

第9课 新概念 22–40 分

笨办法 vs 聪明办法

第①步只点亮了 1 颗。那 10 颗呢——要写 10 遍吗？

笨办法：写 10 遍
np[0] = (0, 80, 0)
np[1] = (0, 80, 0)
np[2] = (0, 80, 0)
np[3] = (0, 80, 0)
# ……一直写到 np[9]
# 10 颗写 10 行，100 颗呢？
VS
聪明办法：for 循环写 1 遍
for i in range(10):
    np[i] = (0, 80, 0)

# 写一遍，自动重复 10 次
# i 每轮 +1：0,1,2,……,9
for i in range(10)：重复 10 次，i 从 0 数到 9——正好对上灯珠编号

第①步大家都点亮一颗了。现在我加个要求：十颗全亮。怎么办？

左边这种写法，能不能跑？能跑。有没有错？没错。就是啰嗦。而且十颗还好，一百颗呢？

右边这两行，做的事情一模一样。我们来读一读右边：for i in range(10)，翻译成人话就是「重复 10 次，每次让 i 变一个数，从 0 数到 9」。

来玩个游戏。这一排同学，从 0 开始报数——0、1、2、3……好。现在我说「第 i 个站起来」，i 从 0 数到 9，每个人轮流站。

看清楚了吗，我只说了一句话，十个人都动了。这就是 for 循环：写一遍，计算机替我们重复很多遍，每一遍那个 i 都不一样。

而且注意一个巧合——不，这不是巧合：i 从 0 数到 9，灯珠编号也正好是 0 到 9。所以 np[i] 每一轮点的，正好是不同的那一颗灯。

from machine import Pin
import neopixel

np = neopixel.NeoPixel(Pin(5), 10)   # 和第①步一样
for i in range(10):                  # i 从 0 数到 9

np.write()                           # 送一次，整排全亮
和第①步比只多了两行：for 那一行，和缩进的 np[i]；np.write() 挪到了循环外面——十颗填完送一次就够

第②步的提问只有一句话：「在刚才的基础上，请用 for 循环让这 10 颗灯全部点亮成绿色。约束不变。」

注意那六个字——在刚才的基础上。这是分步指挥的关键：你不用把五要素再背一遍，AI 记得上一轮的上下文。约束也只要说「不变」。

右边代码和第①步比，就多了两处。第一，for 那一行。第二，下面那行往里缩进了四个空格——缩进表示「这一行是循环里面的」，这个必须看清楚。

还有一处很重要的不同：np.write() 跑到了循环外面。为什么？因为十颗颜色都填好了，一次性送出去就够了，不用送十次。

第9课 第③步 50–62 分

加延时做动画：流水灯

接着上一步问：「请让灯一颗一颗按顺序亮起来，像流水一样跑过去，每颗之间停顿 0.1 秒，跑完再从头开始。约束不变。」
第③步 · 完整可运行参考代码（流水灯）
from machine import Pin              # 引脚工具
import neopixel                      # 灯带工具箱
import time                          # 时间工具

NUM = 10                             # 灯珠数量
np = neopixel.NeoPixel(Pin(5), NUM)  # 数据脚 GPIO5，管 10 颗灯

while True:                          # 一直重复
    for i in range(NUM):             # i 从 0 数到 9
        np[i] = (0, 80, 0)           # 给第 i 颗填上绿色(R,G,B)
        np.write()                   # 把颜色送给灯带
        time.sleep(0.1)              # 停 0.1 秒
        np[i] = (0, 0, 0)            # 熄灭第 i 颗
        np.write()                   # 再送一次，光就跑起来

第③步，也是今天的目标。提问还是一句话，重点在每颗停顿 0.1 秒和跑完再从头开始这两个要求。

这段比第②步多了三样东西：import time、time.sleep，还有把灯熄灭的那两行。

我们一起读循环里面这五行。给第 i 颗填绿色，送出去，停 0.1 秒，把第 i 颗熄灭，再送一次。然后 i 加一，进下一轮。

关键在哪？关键是熄灭。如果不熄灭会怎么样？灯会一颗一颗留在那儿，最后整排全绿——那叫「填满」，也挺好看，但不是流水。

外面还套了一个 while True，意思是一直重复，跑完最后一颗就从头再来。

现在把这段跑起来。跑通了先别急着改颜色，先盯着灯带看十秒钟，想清楚这道光为什么会「跑」。

i 到底是什么？

↑ 此刻 i = 3：「现在轮到第 3 颗」，下一轮自动 +1

i 是循环的计数器

for i in range(10) 让 i 从 0 走到 9，每一轮 +1，正好对上灯珠编号——所以 np[i] 每轮点的是不同的灯。

动画公式

改一点 ＋ 停一下（sleep）＋ 再改一点 ＝ 会动的光。10 颗灯一瞬间全亮看不出顺序，停一停才看得见「跑」。

今天最容易卡住的就是这个 i。很多同学会问：i 是什么？它是个数字吗？

它是一个会变的数字。上面这排格子就是十颗灯珠，现在绿色的是第 3 颗，说明此刻 i 等于 3。下一轮呢？i 自动加一，绿色就跳到第 4 颗。

所以 i 的意思只有一个：现在轮到第几颗。

第二件事，动画是怎么来的。如果十颗灯一瞬间全亮，你看得出顺序吗？看不出，你只会觉得「啪」一下全亮了。

但如果亮一颗、停一下、再亮下一颗，你的眼睛就看到一道光在跑。

所以记住这个公式：改一点，停一下，再改一点，就等于会动的光。你们待会儿把 sleep 的 0.1 改成 0.5 试试，光会跑得慢很多；改成 0.01，又会快到看不清。

都做得差不多了，停一下，看屏幕。这段代码是 AI 很常见的一个回答。我把它传到板子上——运行了，不报错，一行红字都没有。

但是灯带呢？一片漆黑。

这就是本阶段最重要的一件事：AI 是我们的实习程序员，实习生把活儿交上来，不报错不等于做对了。别急着重新提问，先做验收三查：第一，能跑吗？能跑。第二，效果对吗？不对。第三，有没有看不懂的魔法？暂时没有。

问题出在第二条，那就追问，不要重开一轮。这么说：「灯全都不亮，是不是少了把颜色送到灯带的那一步？请检查并补上。」

AI 自己就认错了：少了 np.write()。

记住这句话——给灯填颜色只是填了表，np.write() 才是把表寄出去。AI 也会忘记寄。所以验收，永远是我们自己的活儿。
