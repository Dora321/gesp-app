我们先换一个想法。

菜鸟看到红字，心里咯噔一下：完了完了，我是不是把电脑搞坏了？

高手看到红字，第一反应是什么？太好了。

为什么太好了？因为红字会说话——它告诉你错在第几行、是什么类型的错。这等于有人直接把答案的位置指给你看了。

那高手最怕什么？

最怕不报红字，但结果就是不对。灯也亮了，屏幕也出字了，就是效果反的。电脑觉得一切正常，不吭声。

那种错才叫真麻烦。今天我们会专门抓一只。

最后说一句：排错，英文叫 Debug，直译是「捉虫」。这不是失败，这是程序员的日常工作。写代码的时间和捉虫的时间，差不多一半一半。

第5课 三类错误 8–18 分

三种猎物，三种抓法

先认清它是哪一种，才知道往哪儿找

① 语法错 SyntaxError

拼写格式错了：少写冒号、拼错单词、括号没配对。红字直接指到那一行。

② 运行错 NameError / ImportError

找不到东西：忘了 import、引脚号不存在、库没上传。跑起来才报。

③ 逻辑错（没有红字！）

思路反了：代码全合法，电脑照做，但做出来的不是你想要的。它不吭声。

前两种红字会告诉你；第三种——只能靠你自己看现象倒推

今天的猎物分三种，我们一个一个认。

第一种，语法错，英文 SyntaxError。就是拼写格式写错了：少写一个冒号、单词拼错、括号没配对。

这种最好抓，因为红字会直接指到那一行，PyCharm 还会画红波浪线。

第二种，运行错。它有好几个名字：NameError、ImportError、OSError。共同点是——找不到东西。

忘了 import、引脚号不存在、库没上传，都属于这类。它的特点是：写的时候没事，跑起来才报。

第三种，最难的：逻辑错。

它完全不报红字。代码每一行都合法，电脑老老实实照做了，但做出来的不是你想要的。

比如我们第 3 课那个——按下灯灭、松开灯亮。电脑错了吗？没有，它完全按你写的做了。是你脑子里的逻辑搞反了。

记住这个区别：前两种，红字会告诉你；第三种，只能靠你自己看现象倒推。

第5课 读报错 18–30 分

红字只看最后两行

一大堆英文别慌——有用的就那两行

1
倒数第二行：写着 line 10 —— 告诉你错在第几行附近
2
倒数第一行：写着 SyntaxError —— 告诉你是什么类型的错
3
中间那一大堆？那是电脑自己的「行军路线」，不用看
4
先跳到那一行，用眼睛扫：冒号？括号？拼写？缩进？
5
实在看不出来——别瞎改，把红字全部复制扔给 AI
读报错三要素：哪一行 · 什么错 · 怎么办

看到一大堆英文别慌。我教你们一个诀窍：只看最后两行。

倒数第二行，里面有个词 line 加一个数字，比如 line 10。这告诉你——错在第 10 行附近。

注意我说的是「附近」，不是「就在第 10 行」。有时候真正的错在上一行，电脑是跑到第 10 行才发现不对的。

倒数第一行，写着 XxxError。这告诉你是什么类型的错。

中间那一大堆呢？那是电脑自己的「行军路线」，记录它是怎么一步步跑到出错的地方的。不用看。

所以流程是：先跳到那一行，用眼睛扫一遍——冒号写了吗？括号配对吗？单词拼对了吗？缩进齐吗？

实在看不出来怎么办？别瞎改。瞎改会越改越乱，本来一个错能改出三个。

正确做法：把红字全部复制，扔给 AI。下一页就是模板。

第5课 工具 18–30 分

调试 Prompt 模板

搞不定就找 AI——但要按这个格式问

照着填三行

第1行我运行代码时报错了。这是我的代码：（粘贴代码）
第2行这是下方的红色报错信息：（粘贴全部红色报错文本）
第3行请告诉我错误在哪一行、原因是什么，以及修改后的正确代码。

三条注意事项

①红字必须从第一行到最后一行全部复制——贴一半 AI 也猜不出
②代码也要一起贴，只贴报错 AI 看不到上下文
③三个问题一起问：哪一行、为什么、怎么改
④AI 改完先看懂再上传——别当复读机
⑤逻辑错没有红字，这个模板用不上——得描述症状
AI 瞬间就能变成你的 Debug 助手——前提是你把线索给全

这是今天最实用的一个工具，照着填三行。

第一行：我运行代码时报错了，这是我的代码——把代码粘上去。

第二行：这是下方的红色报错信息——把全部红字粘上去。

第三行：请告诉我错误在哪一行、原因是什么，以及修改后的正确代码。

右边五条注意事项，我挑三条重点说。

第一条最重要：红字必须从第一行到最后一行全部复制。我知道你们会偷懒只复制最后一行——贴一半，AI 也猜不出。

第四条：AI 改完之后，先看懂再上传。不要当复读机。为什么？因为它有时候会顺手把别的地方也改了，你不看就不知道。

第五条特别注意：逻辑错没有红字，这个模板用不上。那种情况你得描述症状——「我想要按下亮，但实际是松开才亮」。

把线索给全，AI 瞬间就能变成你的 Debug 助手。

第5课 模拟实战 30–40 分

Bug 1：少了一个冒号

我们一起抓第一只——这是最好抓的一种

bug1.py
from machine import Pin
import time
led = Pin(2, Pin.OUT)
while True       # 这里漏了冒号 :
    led.value(1)
    time.sleep(0.5)
    led.value(0)
    time.sleep(0.5)

① 语法错 SyntaxError

while True 后面漏了冒号。红字会指到这一行，PyCharm 里它下面还有一条红波浪线。

改法

在 while True 后面补一个英文冒号 :，然后 Ctrl+S 保存再上传。

注意是英文冒号——中文的 ： 电脑不认，改了也照样报错

我们一起抓第一只，这是最好抓的一种。

看代码，第 4 行：while True，后面什么都没有。

再看下面的红字：倒数第二行 line 4，倒数第一行 SyntaxError。

line 4 —— 跳到第 4 行。SyntaxError —— 语法错，说明是拼写格式的问题。

现在用眼睛扫第 4 行：while 拼对了吗？对。True 大写了吗？对。那还差什么？

（等他们喊「冒号」）

对！冒号。前面几课我们写 while True 的时候，后面都跟着一个冒号，今天它不见了。

另外看 PyCharm，它已经在那一行下面画了一条红波浪线——软件其实早就提醒你了，只是你没注意。

改法很简单：补一个冒号，Ctrl+S 保存，上传。

最后提醒一个坑：一定要是英文冒号。你要是用中文输入法打了一个全角的「：」，电脑不认，改了照样报错——而且这个错超级难发现，因为两个看起来几乎一样。

第5课 找错顺序 50–75 分

错误类型卡：按顺序抓

不是碰运气，是一类一类排除

1
① 漏东西 —— 漏 import、漏冒号、漏括号（对应 Bug 1、Bug 2）
2
② 参数错 —— 时间、坐标、量程这些数值不对（对应 Bug 4 的坐标超界）
3
③ 引脚错 —— 代码里的引脚号和实际接线对不上（对应 Bug 4 的 99 号引脚）
4
④ 逻辑反 —— 大小写反、0/1 写反，不报红字但行为相反（对应 Bug 3）
抓到之后要能说出：我是在第几类抓住它的

这张卡人手一份，抓虫就按这个顺序来。

第①类：漏东西。 最常见，先查它。漏了 import、漏了冒号、漏了括号。今天的 Bug 1 和 Bug 2 都是这一类。

第②类：参数错。 数值不对——时间填错了、坐标填错了、范围超了。Bug 4 里的坐标超界就是这类。

第③类：引脚错。 代码里写的引脚号，和你实际接的线对不上。Bug 4 里那个 99 号引脚就是。

第④类：逻辑反。 大小写反、0 和 1 写反。特点是不报红字，但行为相反。Bug 3 就是这一类。

为什么要按顺序？因为①②③红字都会帮你，④红字帮不了你。先把红字能解决的解决掉，剩下的才轮到你动脑子。

还有一个要求：抓到之后，你要能说出——我是在第几类抓住它的。待会儿分享的时候我会问。

改法

开头补一行 import time。你用了一个工具，就得先把它请出来。

第二只虫，Bug 2。

先看红字：NameError: name 'time' isn't defined。翻译过来——我不认识 time 这个东西。

可是代码里明明用了 time.sleep 啊？

对，问题就在这儿：你用了它，但你没有把它请出来。

第 2 行本来应该有一行 import time，现在只剩一句注释。

这就像你跟人说「把扳手递给我」，可工具箱里根本没装扳手——人家当然一脸茫然。

改法：开头补一行 import time。

第5课 最难的一只 50–75 分

Bug 3：一个红字都没有

灯也亮了，程序也没报错——可它就是反的

bug3.py
from machine import Pin
led = Pin(2, Pin.OUT)
btn = Pin(0, Pin.IN, Pin.PULL_UP)
while True:
    if btn.value() == 1:   # 上拉电阻下，按下其实是 0
        led.value(1)
    else:
        led.value(0)

③ 逻辑错（AI 也看不出来）

完全不报红字。电脑觉得代码全对——因为它确实全合法。是我们脑子里的逻辑搞反了：上拉电阻下，按下是 0 不是 1。

怎么抓

只能靠现象倒推：我要的是「按下亮」，实际是「松开亮」→ 说明判断条件反了 → 把 ==1 改成 ==0。

属于第④类：逻辑反——红字帮不了你，AI 也帮不了你，只能靠人

这是今天最难的一只，也是我最想让你们记住的一只。

运行 bug3.py——一个红字都没有。灯也亮了，按钮也有反应。

但是：我要的是「按下亮」，实际却是「松开才亮」。反的。

为什么它不报红字？

因为电脑觉得代码全对啊！你看每一行：拼写对的、冒号有的、缩进齐的。它确实全合法。

是我们自己把逻辑搞反了——第 3 课学过的，上拉电阻下，按下是 0，不是 1。

这种错叫逻辑错。我要强调一句：这种错误 AI 也看不出来。

你把这段代码贴给 AI，问「有什么错」，它多半会说「看起来没问题」。因为从语法上讲确实没问题。

那怎么抓？只能靠现象倒推：

我想要的是什么？按下亮。实际发生了什么？松开亮。两者正好相反 → 说明判断条件反了 → 把 ==1 改成 ==0。

这就是为什么我说，逻辑错必须靠人类自己分析现象。AI 是你的助手，但判断对不对这件事，永远是你的活儿。

第5课 终极挑战 50–75 分

Bug 4：小心，它不止一只

提示：修好第一个错之后别急着庆祝——再运行一次，看看屏幕上真的出字了吗？
bug4.py · 连环错
from machine import Pin, SoftI2C
import ssd1306
i2c = SoftI2C(scl=Pin(22), sda=Pin(99))   # SDA 引脚号写错了
oled = ssd1306.SSD1306_I2C(128, 64, i2c)
oled.fill(0)
oled.text('Hi', 200, 100)   # 坐标超出 128x64 屏幕范围
oled.show()
先报引脚错（第③类）；修好引脚后文字还是不显示——那是坐标超界（第②类）

终极挑战，Bug 4。我先给你们一个警告：它不止一只虫。

运行一下，会先报一个错。按错误类型卡查——第③类，引脚错。第 3 行的 sda 写成了 Pin(99)。

ESP32 根本没有 99 号引脚，所以它报错。改回 21。

改完，很多同学就开始庆祝了：搞定！结果一运行——屏幕还是什么都没有。

而且这次不报错了。

（停顿，让他们想）

第二只虫在哪儿？倒数第二行：oled.text('Hi', 200, 100)。

我们第 4 课学过什么？屏幕多大？128 宽、64 高。那 200 和 100 在哪儿？

在屏幕外面。字确实写了，只是写到看不见的地方去了。

这属于第②类，参数错。改成屏幕里的坐标，比如 (0, 0)。

所以今天最后一个教训：一段代码可能不止一个 bug。修好一个之后，一定要再跑一次验证，别急着庆祝。

课后两件事。

第一件全员都做：回家给家人讲清楚——为什么程序员不怕语法错误，却最怕逻辑错误？

提示你们怎么讲：语法错，电脑会告诉你错在哪；逻辑错，电脑什么都不说，因为它觉得自己没错。

第二件选做，今天特别好玩，叫「给 AI 挖坑」：

你故意写一段有毛病的代码——少个括号、拼错一个字母——然后扔给 AI，看它能不能帮你找出来。

你还可以挖一个逻辑坑试试，看它是不是真像我说的那样看不出来。

下节课带来汇报战况：AI 抓到了几只？漏了哪只？

最后一句：能说清楚「为什么逻辑错最难找」，才是真的懂了。下课，第一阶段毕业快乐！
