# 原卷缺陷题（「争议题」）处置规范

适用：已判定为原卷自身问题、无法按「按原卷改回来」处理的那批题
对象：GESP 一/二级 22 题裁定中归入「原卷争议」的 10 题
制定：2026-11-10

---

## 一、先拆一个概念：「争议」不是一种状态

站内现在的做法是给一个 `official-source-defect` 标记 + 停止计分，把 10 道题装进同一个筐。但这些题的病因根本不是一回事，用同一套处置必然有一半是错的。

按**缺陷落在哪、学生还能不能答**分成四类：

| 类型 | 判据 | 学生能否按命题意图作答 | 处置 | 本次题号 |
|---|---|---|---|---|
| **T1 考点外瑕疵** | 缺陷不在被考的那一处，四个选项仍有唯一解 | 能 | **加注 + 正常计分** | 13、18、20 |
| **T2 多解（双解）** | 两个选项同时成立 | 能答，但选另一个也对 | 保留原文 + 双解标注 + **不计分** | 6、12、14 |
| **T3 代码不成立** | 编译不过，或依赖未定义行为 | 不能，答案取决于编译器 | 保留原文 + 注明 + **不计分** | 17、21 |
| **T4 题面自相矛盾** | 数据范围 / 示例 / 输出格式与程序冲突 | 边界处不能 | 保留原文 + 边界说明 + **不计分** | 16、19 |

### 关键判据（一句话）

> **缺陷是否使考生无法按命题意图作答？不能答的才不计分，能答的必须计分。**

原终稿按「原卷有瑕疵 → 不计分」一刀切，是保守做法。细一层看，13、18、20 三题的缺陷都不在被考的考点上：

- **第 13 题**：缺陷是 `num=1` 时程序不输出，可考点是横线填 `num % i == 0`，B 仍是四个选项里唯一合理的。
- **第 18 题**：缺陷是示例写「层数」、代码写「行数」，可考点是 `now_number = 0` 该放哪，A 仍唯一。
- **第 20 题**：缺陷是首行印成 `i int N, G, R;`，可考点是 L4/L5 的公式该不该改，D 仍唯一。

这三题学生拿到卷子能正常做、也能正常判对错，排除在计分之外反而让题库失真——**真题率下降，而学生的得分率统计里凭空少了 3 道他本来会做的题**。

**修正后的口径：22 题 = 12 题改字段计分 + 3 题加注计分 + 7 题不计分。**

## 二、四类各自怎么做

### T1 考点外瑕疵 → 只加注，不动题面

铁律：**一个字的题面都不要改。** 改了就成「站内原创题」，学生在真实考场遇到原题时反而对不上。

动作只有两个：
1. `examScoring` 保持 `counted`；
2. 解析末尾固定加一段「原卷提示」，写清瑕疵是什么、为什么不影响本题。

### T2 多解 → 不计分，但必须写出「另一个也成立」

这是最容易做错、也最伤学生的一类。

**不计分 ≠ 不解释。** 如果只标「不计分」而解析还按单解写，学生复习时会把"只有 A 对"背下来，下次遇到同类题照错。所以 T2 的解析必须显式写出：除了官方答案，哪个选项也成立、为什么成立、边界在哪。

第 6 题就是反面教材：站内原解析为了维持单解，用「输入 −10 和 −10」去反驳 A——可这个输入根本不满足 A 的前提（一正一负），是**编出来的反例**。这种解析比不写更坏。

### T3 代码不成立 → 保留 + 注明「按命题意图作答」

两道题（17、21）的代码分别依赖未定义行为和无法编译。处置：

1. **绝不修代码补全**（补 `int` 声明、给 `a` 初始化，都会让题变成另一道题）；
2. 解析开头写「原卷代码无法编译 / 属未定义行为」；
3. 补一句「真实考试中遇到此类题，按命题意图选官方答案」；
4. `examScoring` = `excluded`。

第 17 题是个典型陷阱：本机实测输出 `28 28`，看着"能跑出结果"，但那是编译器的偶然行为，换 `-O2` 或换编译器就变。**实测通过 ≠ 题目成立**，这类必须以标准为准。

### T4 题面自相矛盾 → 保留 + 边界说明

第 16 题（"正整数" vs `h=0`）、第 19 题（缺 `(N−1)`，`N=1` 时得 `01−1`）属于这类。缺陷只在边界，主体逻辑成立。处置：保留原文，解析里明确指出边界冲突的具体输入，`examScoring` = `excluded`，但**在「原卷缺陷专题」里可正常使用**（见第四节）。

第 16 题要特别提醒一句：**不要暗改「正整数」为「非负整数」**。改了题就"通"了，可它已经不是真题；而且这种暗改最隐蔽——后续没人看得出这题被动过。

## 三、10 题逐题处置卡（可直接贴进解析字段）

### 卡 1 · 第 6 题（2026-03-l1 #7）T2 双解

```yaml
sourceIntegrity: official-source-defect
defectKind: multi-answer
examScoring: excluded
```

> **答案：B（官方）。但 A 同样成立，本题多解，不计分。**
>
> A 的前提是「一个正数一个负数」，此时 |M−N| = 正数 + |负数|，必大于 0，A 恒真；B 的 |M−N| ≥ 0 对任意 M、N 恒成立。41×41 全枚举验证无例外，A、B 两项同时在所有输入下成立，单选题却给出两个正确答案。
>
> **原卷提示**：站内旧解析用「输入 −10 和 −10」反驳 A，该输入不满足 A 的前提（并非一正一负），属无效反例。真实考试中按官方答案 B 作答。

### 卡 2 · 第 12 题（2024-09-l2 #13）T2 双解

```yaml
sourceIntegrity: official-source-defect
defectKind: multi-answer
examScoring: excluded
```

> **答案：A（官方）。但 B 同样是不正确的说法，本题多解，不计分。**
>
> 题干问「有关说法错误的是」。A 说 `while (1)` 写法错误——`while (1)` 是合法且常见的死循环写法，A 的说法确实错。B 说「输入负数将结束输入，并正确输出」——若**第一次**输入就是负数，`cnt` 仍为 0，随后 `Sum / cnt` 是 `0.0f / 0`，实测输出 `nan`，不能称为正确输出，B 的说法也错。于是 A、B 都是"错误的说法"。
>
> 考点本身讲得清：`while (1)` 合法、`int` 读小数会卡住输入流、`score` 虽未初始化但先被 `cin` 覆盖。可用于讲评。

### 卡 3 · 第 13 题（2024-09-l2 #14）T1 考点外 → **计分**

```yaml
sourceIntegrity: official-source-defect
defectKind: out-of-scope
examScoring: counted
```

> **答案：B（`num % i == 0`）。**
>
> 从 2 枚举到 `num−1`，一旦余数为 0，说明存在 1 和自身之外的约数，输出 `NO` 并退出；循环自然走完则 `i == num`，输出 `YES`。A 在"不能整除"时为真，逻辑正好相反；C 的整数商在循环内几乎不为 0；D 对 `i < num` 的正整数枚举恒不成立。
>
> **原卷提示**：题干称输入为「正整数」，但 `num = 1` 时循环不进入、`i == num` 也为假，程序无任何输出。该缺陷落在横线之外，不影响四个选项的取舍，**本题正常计分**。讲评时可顺带说明 1 既不是质数也不是合数，需要单独判断。

### 卡 4 · 第 14 题（2024-12-l2 #11）T2 双解

```yaml
sourceIntegrity: official-source-defect
defectKind: multi-answer
examScoring: excluded
```

> **答案：A（官方）。但 B 的说法同样不成立，本题多解，不计分。**
>
> A 把 `printf("\n")` 从 L1 移到 L2（内层循环体内），每输出一个算式就换行一次，阶梯形变成单列 45 行，效果不同，A 的说法确实错。
>
> **原卷提示**：选项 B 原卷印作 `print("%c", '\n')`，`print` 不是 C++ 函数，B 根本无法通过编译，其「效果相同」同样不成立。A、B 都是"不正确的说法"。
>
> ⚠️ 站内旧解析末句「注：原题选项印刷若笔误遗漏字母 f，命题意图仍为考查 printf…」**必须删除**——这句话替原卷圆场，与本题的缺陷标记直接矛盾。

### 卡 5 · 第 16 题（2025-03-l2 #27）T4 题面矛盾

```yaml
sourceIntegrity: official-source-defect
defectKind: self-contradictory
examScoring: excluded
```

> **原卷提示：本题不计分。**
>
> 输入格式写「每行一个正整数」，但数据允许 `h = 0`；输出格式写「四个正整数」，而原卷自己的样例输出就是 `2008 2 29 0`，`h'` 为 0。题面与数据范围、与自己的样例互相冲突，`h = 0` 时"正整数"约束无法满足。
>
> 参考程序逻辑正确（闰年判定 + 逐级进位），可作为闰年与时间进位算法的教学样例，但不参与计分。
>
> ⚠️ 不要暗改「正整数」为「非负整数」。

### 卡 6 · 第 17 题（2025-06-l2 #5）T3 未定义行为

```yaml
sourceIntegrity: official-source-defect
defectKind: ub
examScoring: excluded
```

> **原卷提示：本题不计分。**
>
> `int a` 未初始化即被 `b == a` 读取，属未定义行为（UB）。本机 g++ 16.1.0 实测输出 `28 28`，但标准不保证任何取值，换编译器、加 `-O2` 就可能得到别的结果——**能跑出结果不等于题目成立**。
>
> 讲评价值在于考点本身：未初始化变量不可依赖，局部变量的"随机值"是编译器的偶然行为，不是语言保证。

### 卡 7 · 第 18 题（2025-06-l2 #15）T1 考点外 → **计分**

```yaml
sourceIntegrity: official-source-defect
defectKind: out-of-scope
examScoring: counted
```

> **答案：A（不正确）。**
>
> `now_number = 0` 原本在循环外，全程只执行一次，数字 0–9 循环累进；若移到 L1 与 L2 之间，每行开头都重置为 0，每一行都是 `0 1 2 …`，与题干展示的图形完全不符。B（`1 + now_number` 等价）、C（`> 9` 与 `== 10` 对 `now_number` 的取值域等价）、D（`endl` 与 `"\n"` 输出等价）三项都能维持不变。
>
> **原卷提示**：示例首行为「请输入**层数**: 10」，而代码第 4 行是 `cout << "请输入**行数**: "`，两者不一致，属原卷表述瑕疵。该瑕疵不影响 A 的判断，**本题正常计分**。

### 卡 8 · 第 19 题（2025-09-l2 #6）T4 公式边界

```yaml
sourceIntegrity: official-source-defect
defectKind: self-contradictory
examScoring: excluded
```

> **答案：A（官方）。但本题不计分。**
>
> 原卷推导式缺 `(N−1)`，输入 `N = 1` 时得到 `01−1`，而题干说第 1 个应为 `00−0`，边界与题面不符。除数 12 / 10 在 `N ≥ 2` 时仍可唯一确定月份，主体逻辑成立，但 `N = 1` 处自相矛盾。真实考试中按官方答案 A 作答。

### 卡 9 · 第 20 题（2025-09-l2 #15）T1 考点外 → **计分**

```yaml
sourceIntegrity: official-source-defect
defectKind: out-of-scope
examScoring: counted
```

> **答案：D。**
>
> 按 36 克/周期推算：`R = 1..4` 时 L3 正确；`R = 5..7` 应为 `4R − 4`，L4 的 `4R` 偏大 4；`R = 8` 应为 30，L5 的 `6(R−1) = 42` 偏大。必须同时修改 L4 与 L5，选项中没有这个组合，故选 D。
>
> **原卷提示**：原卷首行印作 `i int N, G, R;`（多打一个 `i`），该行无法编译。但缺陷不在被考的 L4 / L5 公式上，考生仍可按命题意图正常作答，**本题正常计分**。讲评时可提一句这是真实存在的印刷错误案例。

### 卡 10 · 第 21 题（2025-09-l2 #19）T3 代码不成立

```yaml
sourceIntegrity: official-source-defect
defectKind: non-compilable
examScoring: excluded
```

> **原卷提示：本题不计分。**
>
> 代码 `x, y, z = 5, 10, 15;` 全无类型声明，无法编译；即便补上 `int`，逗号运算符优先级低于赋值，实际只执行 `z = 5`，`x`、`y` 仍是未初始化，随后 `result = x < y < z` 依赖未初始化值，属 UB。本机实测 `z = 5`（不是 15）。
>
> 站内旧解析「只会把 5 赋给 z」这句是准确的，保留。

## 四、站点字段怎么改

现在只有一个 `official-source-defect` 布尔式标记，装不下上面四类。建议拆成三个字段：

| 字段 | 取值 | 含义 |
|---|---|---|
| `sourceIntegrity` | `ok` / `official-source-defect` | 是否与原卷一致（转录问题在这一层判） |
| `defectKind` | `out-of-scope` / `multi-answer` / `ub` / `non-compilable` / `self-contradictory` | 缺陷类型，决定展示与讲评方式 |
| `examScoring` | `counted` / `excluded` | 是否参与得分统计 |

**关键：`sourceIntegrity` 和 `examScoring` 必须解耦。** 原卷有缺陷（`defect`）不等于不计分（见 T1 三题）。现在这两个概念被绑在一起，是这批题处理别扭的根源。

## 五、三种场景的展示策略

| 场景 | T1（13/18/20） | T2 多解（6/12/14） | T3/T4（16/17/19/21） |
|---|---|---|---|
| **日常练习** | 正常出，正常判对错 | 出，判对错但提示「原卷多解」 | 出，但答完先提示缺陷 |
| **模拟考试** | 正常计入总分 | 排除出卷面（换题补位） | 排除出卷面 |
| **原卷缺陷专题** | 收录，标注"原卷瑕疵、不影响作答" | 收录，作为「多解题」教学素材 | 收录，作为「真实印刷错误」案例 |

第二条特别说明：模考时 T2 一定要换题而不是"留着不计分"——**留着不计分，学生会看到自己有题不算分，产生困惑；排除出卷面最干净。**

## 六、统一解析模板

所有缺陷题的解析都按这四段写，顺序固定：

```
1. 【答案】官方答案 X
2. 【为什么】正常解题逻辑（1–3 句，这部分必须写对，它是题目唯一的剩余价值）
3. 【原卷提示】缺陷是什么 / 落在哪 / 为什么不影响（或为什么影响）作答
4. 【真实考试怎么办】按命题意图作答 / 边界规避
```

第 2 段是最容易被忽略的：**缺陷题不等于废题**。它的解题逻辑仍然是真题逻辑，只是边界或印刷出了问题。把第 2 段写好，这题就还能用；写不好，删掉比留着强。

## 七、一条底线

处理这批题最容易犯的三个错，按危害排序：

1. **暗改题面让它"通"**——最隐蔽，后续无人看得出这题被动过，真题率悄悄失真。凡改了就一定留痕。
2. **为维持单解编造反例**——第 6 题的「−10 和 −10」就是这样来的。宁可标多解，不要编反例。
3. **把「不计分」等同于「不解释」**——学生复习时会把错误结论背下来，比不做这题更糟。

对照着看，这批题真正的价值不在"能不能算分"，而在**它们如实暴露了原卷的边界**。把这层讲给学生，比让他多做三道干净题有用。
