### 重建中发现的两处官方答案问题

1. **2024-12 L4 Q13（插入排序填空）** —— 官方答案表标 **B**（`j = i`），但：
   - `j = i` 时 `while (nums[j] > base)` 即 `nums[i] > nums[i]` 恒假，循环一次不执行；
   - 随后 `nums[j + 1] = base` 变成 `nums[i + 1] = base`，**覆盖下一个元素**。
   - g++ 实测（输入 `{5, 2, 4, 6, 1, 3}`）：A（`j = i - 1`）→ `1 2 3 4 5 6`；
     B（`j = i`）→ `5 2 2 2 2 2`。
   - 本站按技术正确项 **A** 收录，解析首行标注「本题官方答案表标为 B，但 B 会导致
     数组被破坏」，并在证据 JSON 里同时保留 `answerTableValue: 'B'` 与 `official: 'A'`。
2. **2024-09 L4 Q11 原卷笔误** —— 官方程序写 `swap(arr, i, j)`，按冒泡语义应为
   `swap(arr, j, j + 1)`。原卷代码照录，解析中加注，不影响本题填空（只考内层边界）。

### 三卷里最值得记住的判题点

- **2024-06 L4 Q2**：`main` 在 `func` 定义之前调用且无前置声明 → 编译失败。四个
  选项只有 B 有此问题，D 靠 `int func();` 声明而合法。
- **2024-06 L4 Q5**：`int a[2][3]` 的 `a + 1` 跳过**一整行 12 字节**（`a` 是 `int(*)[3]`），
  而 `a[0] + 1` 才是 4 字节。三个写法打印出的地址值相同，加法的步长却不同。
- **2024-09 L4 Q8**：`sizeof(arr[0])` 是 16 而不是 4，`arr[0]` 是一整行 `int[4]`。
- **2024-12 L4 Q7**：`&array[1][1]` 的偏移是 `(1×3+1)×4 = 16` 字节，按 `1+1=2`
  个元素算会得到 `…828` 这个典型错误答案。
- **2024-12 L4 Q12**：`cellRecur(n-1)` 出现了**两次**，递归树是满二叉树 → `O(2ⁿ)`。
  若写成 `int t = cellRecur(n-1); return t + t + 1;`（只调一次）就是 `O(n)`。
