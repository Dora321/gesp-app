# Python 课程内容蓝图

> 目标：解决 Python 课程"内容割裂"问题——让 F1–F7（基础线）与 A1–A9（项目线）形成一条**看得见、可预测、难度连续**的能力进阶，并给每节课一个统一的教学骨架。
>
> 本文是规划文档，不改代码。视觉/外壳层已在前序工作中统一（共享 `PythonLessonShell` + `SlideHeader`）。

---

## 一、诊断：割裂具体在哪

### 1. 单课体量严重失衡
| 课 | 小节数 | 问题 |
|---|---|---|
| F1 Python 入门 | **12** | 把核心语法（变量/IO/类型/运算）和趣味支线（emoji 数学、ASCII 艺术、故事生成器）混在一节，过载 |
| F2 控制流程 | 7 | 结构良好，可作模板 |
| F3 列表与字典 | **3** | list / dict / string 三个大主题各一节，**太薄**——这是最重要的数据结构课却最短 |
| F4 函数与模块 | 7 | 含 lambda（对 GESP 1–3 偏深） |
| F5 绘图魔法 | 11 | 含分形树、蒙特卡洛（趣味支线偏深） |
| F6 随机世界 | **14** | 最臃肿，密码生成器、抛硬币统计等堆在一节 |
| F7 集合宝藏 | 8 | 合理 |

一节 3 小节、另一节 14 小节，学习节奏忽快忽慢。

### 2. 基础线 → 项目线有"断层"
- 基础线在 F3 只教**一维列表**；但 A2（2048）一上来就要**二维列表 + 整局游戏逻辑**（3–4 课时），跨度过大。
- A4 爬虫需要 `requests`/HTTP/环境依赖，A3 AI 需要 KNN/神经网络概念——这两个**环境重、概念深**，却排在项目线第 3、4 位。
- 中间缺一个"**只用 F1–F7 学过的语法，做一个完整小程序**"的桥梁，学生从"会写循环"直接掉进"写游戏/爬虫"。

### 3. 项目线是"领域跳跃"而非"能力阶梯"
当前顺序：A1 算法思维 → A2 游戏 → A3 AI → A4 爬虫 → A5 二分 → A6 加密 → A7 排序 → A8 摩斯 → A9 文件。

同类技能被打散：
- **算法**类（A1 思维、A5 二分、A7 排序）散落在第 1、5、7 位；
- **字符串/字典映射**类（A6 加密、A8 摩斯）和**工具**类（A9 文件）穿插其间；
- 每跳一课就换一个领域，难度不是单调上升的。

### 4. 缺失的核心知识点（项目要用、基础没教）
- **二维列表**（A2、排序网格要用）——F3 只教一维。
- **异常处理 try/except**（A4 爬虫、A9 文件要用）——基础线从未教。
- **2D 坐标/状态建模**（A2、模拟类）——零散出现，没有专门铺垫。

### 5. 每课内部结构不统一
F2 是清晰的"概念阶梯"（布尔→比较→条件→嵌套→for→while→测验）；A1 的递归却是"tab 里套 5 个 tab"。认知负荷和导航方式各课不一。

## 二、统一能力进阶地图

把 16 节重排成**四条有先后的轨道**，每条轨道内部难度单调上升：

```
基础语法线（GESP 1–3 对齐，必修主干）
  F1 入门 → F2 控制流程 → F3 列表/字典/字符串 → F4 函数与模块 → F7 集合
        │
        └─ 应用拓展（用主干技能做可视化/游戏，可选支线）
              F5 turtle 绘图    F6 随机世界

🌉 桥梁（新增 1 节）：用 F1–F7 做一个完整小程序（猜数字 / 文字冒险）
        │
算法线          A1 算法思维 → A5 二分查找 → A7 排序
字符串·工具线   A6 加密解密 → A8 摩斯电码 → A9 文件操作
综合·拓展线     A2 2048 游戏 → A3 AI 初探 → A4 网络爬虫（环境重，放最后/选修）
```

设计原则：
1. **主干必修、支线选修**：F1–F4、F7 是语法主干；F5/F6 是"用主干做东西"的应用，AI/爬虫是兴趣拓展。
2. **同类技能聚成轨道**：算法连着算法，字符串连着字符串，学生在一条轨道里越走越深。
3. **环境依赖的放最后**：爬虫/AI 这类需要外部库或抽象概念的，作为收尾拓展。

## 三、统一的每课模板

每节课固定 **6–8 个小节**，遵循同一骨架（F2 已接近，作为参照）：

1. **导入钩子**（1 节）——一个生活化场景/要做的成品预告，回答"这节学了能干嘛"。
2. **核心概念**（2–4 节）——每节 = 一个概念 + 一个交互演示 + 即时反馈（沿用 `SlideHeader` + 交互组件 + `PyCodeTracer`）。
3. **动手实践**（1 节）——用本课概念现场拼出一个小成品。
4. **自测闯关**（1 节）——`MiniQuiz` 式测验。
5. **小结与衔接**（1 节）——回顾要点 + 明确指向下一课"为什么是它"。

硬性约束：不允许出现 3 小节（太薄）或 12+ 小节（太厚）；不允许 tab 套 tab。

## 五、落地优先级

按"投入产出比 + 风险"排序：

1. **P0 — 补断层**（最高价值）：新增桥梁小程序 + 给 F3 补二维列表 + 给 F4 补 try/except。直接消除"基础→项目"悬崖。
2. **P1 — 削峰填谷**：拆 F1、扩 F3、瘦 F5/F6，让每课落在 6–8 节。
3. **P2 — 项目线重排**：按算法/字符串/工具/拓展四轨道重排 A1–A9，更新 flow 数据。
4. **P3 — 模板对齐**：把每课内部结构统一到第三节的骨架（导入→概念→实践→测验→小结）。

每一步都可独立交付、独立验证（`npm run build` + `npm run check`），不必一次做完。

## 附：与 GESP 的对齐

- **主干（必考向）**：F1 变量/类型/运算、F2 控制流程、F3 列表/字典/字符串、F4 函数、F7 集合、A1/A5/A7 算法——对应 GESP Python 1–4 级的核心考点。
- **拓展（兴趣向）**：F5 turtle、F6 随机、A2 游戏、A3 AI、A4 爬虫——提升兴趣但非考点，适合作选修/作品。

建议在课程中心用"主干 / 拓展"两个标签把这两类显式区分开，让学生（和家长）一眼看清必学路径。
