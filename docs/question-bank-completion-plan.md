## 五、风险与注意事项

1. **转义字符陷阱**：L8 用双引号，脚本需同时匹配单/双引号；选项含 `\'` 在模板字符串中会变成八进制转义，需 `replace(/\\/g, '\\\\')`
2. **压缩行 vs 换行**：执行前先 `grep -c "explanation:" file | head -5` 确认行格式
3. **单文件试跑**：每次批量前先跑 1 个文件 → `node --check` → 人工抽检 3 题 → 再批量
4. **git 干净**：大批量修改前确认 `git status` 干净，出错可 `git checkout --` 一键恢复
5. **L8 编程题外部引入**：`programming.js` 是独立文件，修改后所有 L8 试卷都受影响，改动需谨慎
6. **标签归一化**：L8 的旧标签（"客观题""单选题"等）需先迁移再跑增强脚本，否则 tags 字段会被污染
